01 / 准备

接入 Codex 前，需要准备什么？

Codex 是 OpenAI 的编程工具。这里介绍使用自定义 API 供应商的接入方式，命令行配置以 Codex CLI 为例；其他客户端请使用其对应设置入口。

  • 已经安装可用的 Codex 客户端。CLI 安装方式见 OpenAI 官方文档。
  • 一枚由你选择的 API 服务提供的有效密钥。
  • 与该密钥匹配的 API 地址，以及支持 Codex Responses 请求的模型名称。

下面用 Key智中转演示。它提供第三方 API 中转服务，账户、API Key 和用量在本站管理。ChatGPT 订阅与本站 API 用量分别管理。

02 / 获取参数

创建 API Key，确认可用模型

  1. 注册 Key智中转账户，已有账户可以直接登录。
  2. 进入控制台的 API 密钥 页面，为这次接入创建一枚密钥。
  3. 确认账户额度、密钥分组和允许调用的模型。到 模型广场 查看当前模型信息，复制实际的模型 ID。

03 / 配置

两种配置方式，选择适合你的一种

方式 A：通过 CC Switch 导入

如果已经安装 CC Switch，可在本站 API 密钥列表选择“导入到 CCS”，在弹出的窗口中核对供应商信息，确认导入后将对应供应商切换到“使用中”。随后完全退出并重新打开目标客户端，建立新会话验证。

按钮位置、导入窗口和使用状态都有截图说明：查看 CC Switch 图文接入步骤 →

方式 B：手动配置 Codex CLI

先备份已有配置，再编辑用户目录下的 ~/.codex/config.toml。Windows 默认位置为 %USERPROFILE%\.codex\config.toml；如果设置了 CODEX_HOME，请使用该目录。供应商配置应放在用户级配置中。

合并下面的配置，不要覆盖原有的其他设置；把 YOUR_MODEL_ID 换成你的密钥实际可用、支持 Responses 的模型 ID。同名配置项或表已存在时，直接编辑原值。

config.toml · 用户配置
model_provider = "keyzhongzhuan"
model = "YOUR_MODEL_ID"

[model_providers.keyzhongzhuan]
name = "Key智中转"
base_url = "https://aitokey.top/v1"
env_key = "KEYZHONGZHUAN_API_KEY"
wire_api = "responses"
requires_openai_auth = false

在启动 Codex 的终端会话中设置环境变量。以下以 Windows PowerShell 为例，密钥通过隐藏输入读取，不会写进命令历史：

PowerShell · 输入密钥后启动
$relayCredential = Get-Credential -UserName "api" -Message "密码栏输入本站 API Key"
$env:KEYZHONGZHUAN_API_KEY = $relayCredential.GetNetworkCredential().Password
codex

这个环境变量只对当前终端及其启动的进程生效。另开终端需要重新设置。密钥只在本机输入；反馈问题时请遮盖密钥。

配置项依据 OpenAI 官方配置文档。客户端版本和供应商的功能兼容情况可能不同，其他客户端不要直接照搬 CLI 配置。

04 / 验证

用一次简单对话验证连接

  1. 重新启动目标客户端，确认正在使用刚配置的供应商和模型。
  2. 在新会话发送：“请只回复：连接成功。”
  3. 能够返回内容后，再在自己的项目中测试正常任务。
  4. 到控制台的 使用记录 核对是否出现对应调用；若没有记录，继续检查客户端实际使用的供应商、请求地址和本地网络。

简单对话成功只说明基础请求可用。工具调用、图片输入、长上下文等能力，还需要分别验证模型与接口的支持情况。

05 / 排查

Codex 一直思考、没有响应怎么办？

“一直思考”可能来自模型推理、网络重试、工具等待或请求失败。先看客户端当前状态，再按下面的顺序缩小范围。

  1. 确认是否在等待操作。检查终端是否在等输入、客户端是否在等工具执行或权限确认。
  2. 用新会话发送短问题。短问题也没有响应时，优先检查连接和参数；仅长任务慢时，再检查上下文大小、工具和推理设置。
  3. 核对四个参数。确认 API 地址、API Key、模型 ID 和 Responses 协议相互匹配，尤其注意重复的 /v1。
  4. 检查调用记录和服务状态。看控制台是否收到请求、返回什么错误，并查看 通道状态。记录出现可能有延迟，不能只凭一项判断。
  5. 保留错误信息再重试。保存报错原文、请求时间和请求 ID，便于核查；不要连续提交同一个长任务，以免产生重复调用。

常见 API 错误对照表

现象优先检查下一步
401 鉴权失败密钥错误、已失效或没有传入检查环境变量与供应商配置，必要时重新创建密钥。
403 请求被拒绝权限、模型或访问策略限制阅读错误正文，核对密钥分组和该模型的调用权限。
404 找不到接口或模型路径拼接、模型 ID、协议支持检查有无重复的 /v1，并复制准确模型 ID。
429 限流或配额问题并发、请求频率、额度或上游限制以错误正文为准；降低并发，按重试提示等待，核对额度。
5xx 服务异常网关或上游服务错误查看通道状态，保留请求 ID，稍后重试或联系支持。
超时、流式中断网络、代理、长连接或上游响应用短问题复现，检查代理和网络，再对照调用记录。

错误码只是定位线索，同一状态码可能对应不同原因。以接口返回的具体错误正文和调用记录为准。

06 / 常见问题

接入前后，你可能还想知道

有 ChatGPT 订阅，还需要本站 API Key 吗？

使用本文的第三方 API 接入方式，需要本站创建的 API Key。ChatGPT 登录凭证不能当作本站密钥使用；账户额度请分别查看对应服务。

为什么改了配置还是使用旧供应商？

检查修改的是当前使用的用户配置目录，是否存在其他配置覆盖，以及是否打开了旧客户端进程。用当前终端重新启动 CLI，在新会话中核对供应商与模型。

能直接把任意模型名称填进去吗？

不能。模型必须同时满足密钥有权限、接口可用、支持 Codex 所需 Responses 请求。请使用控制台显示的准确模型 ID。

基础对话成功，为什么工具调用仍然报错？

文本生成成功不代表所有工具都兼容。检查所选模型与供应商对工具调用、图片输入、上下文和流式响应的支持，并保留具体失败信息。
