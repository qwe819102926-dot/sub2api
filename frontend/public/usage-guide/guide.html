After login / setup notes

登入之后，这样配置。

先在 key智中转 创建 API 密钥，再按客户端选择： CC Switch、Codex++、WorkBuddy、ZCode， 或在 ChatGPT 客户端里接入 Grok / DeepSeek / Kimi / GLM。

配置流程图

前三步共用。创建密钥后，按你实际使用的客户端选择路径。

01 / START 登录官网 打开 aitokey.top，进入账号。
02 / KEYS API 密钥 左侧账户菜单进入“API 密钥”。
03 / CREATE 创建密钥 命名并选择分组后创建。
04 / FORK 选择客户端 按客户端选择后续路径。
Path E ChatGPT 客户端 用 Grok / DeepSeek / Kimi / GLM，填请求地址和模型映射。 Path A 导入 CC Switch 在密钥行点击“导入到 CCS”，确认供应商后切到“使用中”。 Path B 添加到 Codex++ 在供应商配置里填写名称、纯 API、Base URL 和 Key，保存后启动。 Path C 接入 WorkBuddy 自定义接口地址填 completions，填写模型和 API Key 后保存。 Path D 接入 ZCode 模型设置里填写 Base URL、Responses 格式、API Key 和模型后启用。

Visual walkthrough

按截图，一步一步完成

每一步都配了对应截图和实际操作说明。点击截图可以放大查看红框位置。

01

打开官网并登录

登录入口

进入 aitokey.top 首页，在页面中间的按钮区域点击“登录”。 如果你已经在登录状态，通常会直接进入管理页面。

这一页要做什么

  1. 打开 aitokey.top/home。
  2. 点击页面中间的“登录”按钮。
  3. 完成账号验证后进入后台。
打开登录页 ↗
02

进入“API 密钥”页面

账户菜单

登录后，在左侧“我的账户”区域找到 API 密钥。页面顶部会显示 API 端点、图片请求地址和 WorkBuddy 等常用入口。

找到创建入口

  1. 确认左侧菜单已选中 API 密钥。
  2. 查看右上角的黑色 “创建密钥” 按钮。
  3. 如果列表没有刷新，先点击旁边的刷新按钮。
https://aitokey.top/keys
03

创建密钥并选择分组

关键配置

点击“创建密钥”后，先填写一个容易识别的名称，再打开“分组”下拉框。 选择与你要使用的模型对应的分组，截图中展示了 GPT、测试模型、gpt6 智商、探针、OpenAI raykey 等选项。

填写方式建议

  1. 名称可以写成 主密钥 或客户端名称，方便以后识别。
  2. 点击“选择分组”，按需要选择模型组。
  3. “密钥有效期”如果不需要自动过期，可以保持关闭。
  4. 确认后点击右下角 “创建”。
04

创建完成后，选择一条路径

在这里分叉

密钥列表的操作区可以走两条路：点击 “导入到 CCS” 进入 CC Switch， 或先复制密钥，再打开对应客户端手动添加。下面五个入口可以直接跳到对应配置。

先看清操作区

  1. 使用密钥：查看或复制该密钥，走 Codex++、WorkBuddy、ZCode、ChatGPT 客户端时会用到。
  2. 导入到 CCS：把配置发送到 CC Switch。
  3. 后面的“禁用、编辑、删除”先不要操作。
Path E ChatGPT 客户端 Grok / DeepSeek / Kimi / GLM，方法同理。 Path A · 左屏 导入 CC Switch 点击“导入到 CCS”，确认供应商后切到“使用中”。 Path B · 右屏 添加到 Codex++ 复制密钥，到供应商配置里填写、保存并启动。 Path C 接入 WorkBuddy 自定义接口地址和模型后保存。 Path D 接入 ZCode 模型设置里填写供应商后启用。

Steps

01 登录官网 02 API 密钥 03 创建密钥 04 选择路径 E ChatGPT 客户端 A 左屏 CCS B 右屏 Codex++ C WorkBuddy D ZCode

路径 A · 导入 CC Switch

从密钥行的“导入到 CCS”开始，确认供应商配置，再把状态切到“使用中”。

CC Switch
A1

在密钥列表导入到 CCS

连接客户端

在刚刚创建的那一行找到操作区，点击 “导入到 CCS”。不要点击“禁用”或“删除”。

这一步点哪里

  1. 确认当前行是刚创建的密钥。
  2. 点击操作区里的 导入到 CCS。
  3. 等待 CC Switch 弹出供应商配置窗口。
如果没有看到按钮，先确认 CC Switch 是否已安装，并刷新密钥列表。

还没有 CC Switch？先下载安装

官方渠道：访问 ccswitch.io 了解软件，下载安装包请进入官方 GitHub Releases。

访问 CC Switch 官网 ↗ 下载客户端 ↗
A2

确认供应商配置并切换使用

完成导入

点击导入后，CC Switch 会弹出供应商配置确认窗口。核对应用类型、供应商名称、 API 端点、模型和用量查询状态，确认无误后点击右下角蓝色 “导入”。

导入前检查

  1. 应用类型应为 Codex。
  2. 供应商名称应为 key智中转。
  3. API 端点为 https://aitokey.top。
  4. 确认信息后点击 导入。
A3

在 CC Switch 中确认“使用中”

验收状态

导入完成后，在 CC Switch 的供应商列表中找到 key智中转。 该卡片出现“使用中”状态，并显示余额或剩余额度，说明配置已经生效。

完成标准

  1. 列表中能看到 key智中转。
  2. 卡片状态显示 使用中。
  3. 余额查询正常，没有显示“查询失败”。
  4. 之后即可在 CC Switch 中使用对应模型。
A4

重启 ChatGPT 客户端

最后一步

CC Switch 显示“使用中”后，完全退出当前的 ChatGPT / Codex 客户端， 再重新打开客户端，让刚导入的供应商配置加载生效。

这样操作就可以了

  1. 先完全退出 ChatGPT / Codex 客户端。
  2. 重新打开客户端，等待首页加载完成。
  3. 新配置加载后，就可以使用 key智中转 的模型了。
如果重启后仍未生效，请确认 CC Switch 中的 key智中转 仍显示“使用中”，再重新启动一次客户端。

路径 B · 添加到 Codex++

不走“导入到 CCS”。复制密钥后，在 Codex++ 管理工具里手动添加供应商，保存后再启动。

Codex++
B1

在 Codex++ 填写供应商配置

手动添加

打开 Codex++ 管理工具，左侧进入 供应商配置。 按截图填写名称、接入模式、模型、Base URL 和 Key，确认上游协议后保存。

按红箭头填写

  1. 左侧点击 供应商配置。
  2. 名称填写 key智中转。
  3. 接入模式选择 纯 API。
  4. 配置模型填写你要使用的模型名，截图示例为 gpt-5.6-sol。
  5. Base URL 填写 https://aitokey.top。
  6. Key 粘贴刚才在密钥列表复制的 API 密钥。
  7. 上游协议选择 Responses API，然后点击 保存此模型。
https://aitokey.top
“启用目标功能”保持关闭即可。Key 只粘贴到 Codex++，不要发到聊天或截图公开。
B2

回到概览并启动 Codex++

生效

供应商保存后，回到左侧 概览。健康检查正常时，点击 “启动 Codex++”，让刚保存的供应商配置加载生效。

启动前看一眼

  1. 左侧回到 概览。
  2. 确认 Codex 版本、应用和入口都显示正常。
  3. 点击蓝色按钮 启动 Codex++。
如果启动后没有走新配置，回到供应商配置确认已点击“保存此模型”，再重新启动一次。
B3

重启 ChatGPT 客户端

最后一步

Codex++ 启动完成后，完全退出当前的 ChatGPT / Codex 客户端， 再重新打开客户端，让刚保存的供应商配置加载生效。

这样操作就可以了

  1. 先完全退出 ChatGPT / Codex 客户端。
  2. 重新打开客户端，等待首页加载完成。
  3. 新配置加载后，就可以使用 key智中转 的模型了。
如果重启后仍未生效，请回到 Codex++ 概览再点一次“启动 Codex++”，然后重新打开客户端。

路径 C · 接入 WorkBuddy

复制密钥后，在 WorkBuddy 的模型设置里用自定义接口添加模型。

WorkBuddy
C1

编辑模型并填写接口

自定义 API

打开 WorkBuddy，进入 模型 设置，点击添加或编辑模型。 提供商选自定义，接口地址填 completions，再粘贴 API Key 和模型名称。

按红箭头填写

  1. 提供商选择 自定义 / Custom。
  2. 接口地址填写 https://aitokey.top/v1/chat/completions。
  3. API Key 粘贴刚才复制的密钥。
  4. 模型名称填写你要使用的模型，截图示例为 gpt-5.6-sol。
  5. 高级配置勾选 自定义协议，需要时再打开工具调用、图片输入、推理模式。
  6. 确认后点击右下角 保存。
https://aitokey.top/v1/chat/completions

路径 D · 接入 ZCode

在 ZCode 的模型设置里添加自定义供应商，填写 Base URL、API 格式、Key 和模型后启用。

ZCode
D1

在模型设置里添加供应商

自定义供应商

打开 ZCode，左侧进入 模型设置。添加自定义供应商后， 填写 Base URL、API 格式、API Key 和模型列表，确认状态为已启用。

按红箭头填写

  1. 左侧点击 模型设置，再添加自定义供应商。
  2. Base URL 填写 https://aitokey.top。
  3. API 格式选择 Responses (/responses)。
  4. API Key 粘贴刚才复制的密钥。
  5. 模型列表添加你要使用的模型，截图示例为 gpt-5.5。
  6. 确认右上角状态为 已启用。
https://aitokey.top

路径 E · ChatGPT 客户端用 Grok / DeepSeek / Kimi / GLM

以 Grok 为例。DeepSeek、Kimi、GLM 的填法完全同理，只换模型名。

ChatGPT
这几个全部同理：API 请求地址都填 https://aitokey.top，上游格式都选 Responses（原生）。 默认模型和映射行换成对应名称即可，比如 grok-4.6、deepseek-chat、kimi-k2、glm-4.6。
E1

填写 API Key、请求地址和默认模型

以 Grok 为例

打开 ChatGPT / Codex 客户端的供应商编辑页，填好 API Key、请求地址和默认模型。 截图用的是 Grok，其他模型只改这一行名称。

先填这三项

  1. API Key 粘贴刚才复制的密钥。
  2. API 请求地址填写 https://aitokey.top，不要打开“完整 URL”。
  3. 默认模型填写 grok-4.6。DeepSeek / Kimi / GLM 换成对应模型名。
  4. 上游格式保持 Responses（原生）。
https://aitokey.top
E2

补上模型映射

菜单显示

继续往下找到 模型映射。菜单显示名和实际请求模型填同一套名称， 这样客户端里才能选到这些第三方模型。

映射这样填

  1. Grok 示例：grok-4.5 → grok-4.5，grok-4.6 → grok-4.6。
  2. DeepSeek / Kimi / GLM 同理，左右两列都填对应模型名。
  3. 保存后重启 ChatGPT / Codex 客户端，模型列表才会刷新。
改映射后必须重启客户端，/model 命令才能看到这些第三方模型名。
