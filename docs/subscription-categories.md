# 订阅模型分类

订阅页继续通过 `GET /api/v1/payment/checkout-info` 一次加载套餐。分类切换只筛选已加载的数据，不触发接口请求，不改变套餐对象、订单或支付状态。

## 分类来源与配置

- 套餐关联业务分组 `group_id`，接口返回分组平台 `group_platform`。后台创建套餐时可先筛选模型分类，再选择对应平台的订阅分组；保存仍使用原有 `group_id`。
- `openai` → GPT订阅，`anthropic` → Claude订阅，`deepseek` → DeepSeek订阅，其他平台（含综合分组、缺失或未知平台）→ 其他模型。不按套餐名称推断分类。
- 映射及分类顺序集中在 `frontend/src/components/payment/subscriptionCategories.ts` 的 `SUBSCRIPTION_CATEGORIES` 中，调整 `sortOrder` 即可修改展示顺序。此项为代码配置，当前不提供后台拖拽排序。
- 分类内沿用套餐原有 `sort_order`（后台套餐编辑的“排序”），数字越小越靠前，同值按套餐 ID 稳定排序。
- 数量来自当前接口返回的在售套餐；无套餐的分类隐藏。所有分类均无套餐时沿用空状态。默认显示排序最前的非空分类。

## 兼容与限制

无需数据库迁移或后端接口调整，未执行生产数据库操作。已有套餐、定价、原价、额度、倍率、有效期、购买及续费逻辑保持不变。

分类与现有业务分组平台关联，同一平台分组归入同一分类。当前不支持在保持业务分组不变的前提下，为某个套餐独立指定其他分类。不要为改变展示分类而改动现有分组平台；若未来需要独立分类，应另外评审可空分类字段、旧客户端兼容及回填迁移方案。
